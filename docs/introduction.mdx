## First call in a minute

<Steps>
  <Step title="Install the SDK">
    ```sh
    pnpm add juno-sdk
    ```
  </Step>
  <Step title="Initialize with your project API key">
    ```ts
    import juno from 'juno-sdk';

    juno.init({
      apiKey: process.env.JUNO_API_KEY!,
      baseURL: 'https://api.juno.bitsofgood.org',
    });
    ```

  </Step>
  <Step title="Look up your project">
    ```ts
    const project = await juno.project.getProject({ id: 12 });
    console.log(project); // { id: 12, name: 'Your Project' }
    ```
  </Step>
</Steps>

Need a key first? The [quickstart](/getting-started) walks through requesting an account and creating one in the dashboard.

## How Juno fits into your project

<Columns cols={3}>
  <Card title="Dashboard" icon="gauge" href="https://juno.bitsofgood.org">
    Request an account, manage project access, create API keys, and configure
    services.
  </Card>
  <Card title="SDK" icon="js" href="/sdk-reference">
    Call Juno from JavaScript or TypeScript with the `juno-sdk` package.
  </Card>
  <Card title="API gateway" icon="server" href="/api-reference/introduction">
    Receives HTTP requests and routes them to Juno's internal services. Call it
    directly or through the SDK.
  </Card>
</Columns>

A Juno **project** groups your team's members and service configuration. API keys belong to a project and an **environment**, such as `dev` or `prod`. Use the key for the environment whose configuration you want to access.

<Note>
  Juno user accounts manage infrastructure access. They are separate from the
  end-user accounts in your own application.
</Note>

## Contributing to Juno

You can use hosted Juno without running its services locally. If you are working on Juno itself, follow [Local development](/local-development) to run the Docker stack or test a local SDK build.
