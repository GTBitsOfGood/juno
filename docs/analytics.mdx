Juno analytics stores application events in Juno's database. It is separate from [email delivery statistics](/email#delivery-statistics), which come from SendGrid.

Click, visit, input, and custom events all write to Juno's own Postgres through the analytics-service. There is no external analytics provider. You do not need `clientAnalyticsKey` or `serverAnalyticsKey` to log or query events through the API or SDK. Those fields still exist on the leftover `juno.analyticsConfig` API (and the dashboard still has a form for them) from when events were stored in a separate service.

These methods are on the SDK's `main` branch and are intended for `0.0.12`. If that release is not yet available from your package registry, follow [Using a local SDK build](/local-development#using-a-local-sdk-build).

## Log and read a visit event

After [initializing the SDK](/getting-started) with a project API key:

```ts
const event = await juno.analytics.logVisitEvent({
  pageUrl: 'https://example.org/home',
  userId: 'user-123',
});
console.log(event.id);

const { events, afterId } = await juno.analytics.getVisitEventsPaginated({
  projectName: 'Your Project',
  environment: 'prod',
  limit: 20,
});
console.log(events, afterId);
```

The API key's project and environment are used when writing the event. `userId` is an identifier you choose for a user in your own application, not a Juno account id. `afterId` is an opaque pagination cursor.

Click, input, and custom events follow the same pattern (`logClickEvent`, `logInputEvent`, `logCustomEvent`, plus the matching `get*EventsPaginated` and `getAll*` methods). See the [SDK reference](/sdk-reference#analytics).

## Optional user and project credentials

Paginated and "get all" reads accept an optional second `{ userJwt, projectId }` argument when acting on behalf of a signed-in user. The log methods do not take that argument. See [Acting for a signed-in user](/authentication#acting-for-a-signed-in-user).
